취재 자료 자동 수집 파이프라인

공개기록·웹에서 필요한 자료를 모아오기 — API · Playwright MCP · Scrapling

보관본 안내 — 이 문서는 현행 커리큘럼에 포함되지 않음. 여기 내용은 2차 실습 2막 · 취재의 전반(모으기)으로 통합됐음. 새로 시작하는 경우 학습 허브 → 1막 · 기획부터 진행할 것. 이 문서는 수집 방법을 따로 참고할 때만 사용.

대상: 1차·탐사취재 실습을 마친 기자
도구: Claude Code + 공개 API(DART·국회·재정·법령·빅카인즈) + Playwright MCP + Scrapling
목표: 취재 주제 한 마디로 여러 공개 소스에서 자료를 자동 수집해 sources/에 모으고, 곧바로 개체 추출·검증으로 연결
핵심 원칙: 공개기록과 이용약관 안에서, 로그인 우회 없이. 수집은 자동, 판단과 게재는 사람

1. 무엇을 만들고, 무엇을 경험하나

"이 주제 자료 수집해줘" 한 마디면 소스별 최적 방법으로 자료를 모아 sources/에 저장합니다.

"<취재 주제>" 한 마디
   │
   ▼ 주제를 검색어·기관·기간으로 구체화
   │
   ├─ DART 공시 · 국회 의안 · 재정 · 법령 · 뉴스   → API 스킬(python 실행)
   ├─ 부처 보도자료 · 로그인/JS 페이지            → Playwright MCP
   └─ 안티봇·구조 변경 잦은 사이트                → Scrapling
   │
   ▼ 원문을 sources/ 에 저장 + 출처를 meta/collection_log.md 에 기록
   │
   ▼ (이후) 탐사취재 실습으로 넘겨 개체 추출·교차검증

경험하는 것은 세 가지 수집 방식과, 그것을 하나로 묶는 에이전트입니다.

  • API(1순위): 구조화된 공개기록은 공식 OpenAPI로 받는 것이 가장 정확하고 합법적입니다.
  • Playwright MCP(2순위): API가 없거나 로그인·자바스크립트 렌더링이 필요한 페이지는 브라우저를 조작해 받습니다.
  • Scrapling(3순위): 안티봇이 있거나 화면 구조가 자주 바뀌는 사이트는 적응형 스크래핑으로 견고하게 받습니다.

2. 소스별 최적 수집 방법

먼저 API를 찾고, 없을 때만 브라우저·스크래핑으로 내려갑니다.

소스 1순위 방법 도구 비고
기업 공시(DART) API opendart OpenAPI 무료 키, 공시목록·원본
국회 의안·회의록 API 열린국회정보 OpenAPI(open.assembly.go.kr) 무료 키
예산·재정 API 열린재정 OpenAPI(openfiscaldata.go.kr) 무료 키
법령·판례 API 국가법령정보 OpenAPI(open.law.go.kr) 판결서 전문은 열람 제한
뉴스 대조 API 빅카인즈 API(BIGKINDS-LAB) 개체 언론 등장 확인
부처 보도자료 브라우저/스크랩 Playwright MCP 또는 Scrapling 정책브리핑·부처 사이트
로그인·JS 페이지 브라우저 Playwright MCP 검색폼·페이지네이션
안티봇·잦은 개편 스크랩 Scrapling 적응형 선택자

판결서 인터넷열람처럼 본인확인·목적 제한이 있는 자료는 자동 수집하지 않습니다. 로그인 우회는 금지이며, 필요하면 사람이 직접 열람합니다.

4. 준비

4-1. Claude Code 실행과 도구

mkdir agent_collector && cd agent_collector
claude

API 호출과 스크래핑에 파이썬을 씁니다. 파이썬이 설치돼 있어야 하며(사전 준비에서 설치), 패키지는 가상환경(.venv)에서 pip로 설치합니다.

python -m venv .venv
source .venv/bin/activate        # Windows(PowerShell): .venv\Scripts\activate
pip install requests python-dotenv

.venv/와 .env는 .gitignore에 넣어 공유되지 않게 합니다.

4-2. API 키 발급 후 .env

각 포털에서 무료 키를 발급받아 .env에 넣습니다(키는 공유·커밋 금지, .gitignore에 .env 추가).

DART_API_KEY=발급키
ASSEMBLY_API_KEY=발급키
BIGKINDS_API_KEY=발급키

4-3. Playwright MCP 연결

브라우저 조작이 필요한 소스를 위해 Microsoft Playwright MCP를 붙입니다. 구조화된 접근성 트리를 쓰므로 화면 캡처 없이 빠릅니다.

claude mcp add playwright npx @playwright/mcp@latest

/mcp로 연결을 확인하고, 처음 도구를 쓸 때 권한을 물으면 허용합니다.

4-4. (선택) Scrapling — 안티봇·적응형 스크래핑

구조가 자주 바뀌거나 안티봇이 있는 사이트용입니다. 라이브러리로 쓰거나 내장 MCP로 붙일 수 있습니다.

pip install scrapling
scrapling install               # 브라우저·핑거프린트 의존성 설치 (.venv 활성화 상태)

MCP로 붙이려면(선택):

pip install "scrapling[mcp]"
claude mcp add scrapling -- .venv/bin/scrapling mcp-server

Scrapling은 페이지에서 필요한 부분만 먼저 추출해 AI에 넘겨, 토큰을 아끼고 선택자가 깨져도 스스로 위치를 다시 찾습니다.

5. 설정 파일 만들기

5-1. CLAUDE.md

# 취재 자료 자동 수집 프로젝트 규칙

## 역할과 원칙
- 너는 취재 자료 수집 담당이다. 판단과 게재 책임은 사람 기자에게 있다.
- 공개기록과 이용약관 안에서만 수집한다. 로그인 우회·본인확인 회피는 하지 않는다.
- 수집한 모든 파일에 출처(URL·수집일·소스명)를 남긴다.
- 자료를 지어내지 않는다. 못 받으면 실패로 기록하고 사람에게 알린다.

## 입력/출력
- 수집 결과 원문: sources/
- 수집 로그: meta/collection_log.md
- API 키: .env

## 소스별 방법 (API 우선 → 브라우저 → 스크랩)
- DART·국회·재정·법령·뉴스: fetch-records 스킬(공식 OpenAPI, python 실행).
- 보도자료·로그인/JS 페이지: Playwright MCP로 검색·다운로드.
- 안티봇·잦은 개편: Scrapling으로 견고하게 수집.
- 판결서 인터넷열람 등 제한 자료: 자동 수집하지 않고 사람에게 넘긴다.

## 작업 파이프라인 ("<주제> 자료 수집해줘"라고 하면)
1. 주제를 검색어·기관·기간으로 구체화한다.
2. 소스별 최적 방법으로 자료를 받아 sources/에 저장한다.
3. 각 파일의 출처를 meta/collection_log.md에 기록한다.
4. 소스별 수집 건수·실패·제한을 표로 보고한다.

## 윤리·법
- robots.txt와 이용약관을 지키고, 요청 간 간격을 둔다(과도한 트래픽 금지).
- 저작권 있는 본문은 수집·인용 범위를 지키고, 개인정보는 최소화한다.
- 제한된 자료의 접근을 우회하지 않는다.

5-3. 스킬 — .claude/skills/fetch-records/SKILL.md

---
name: fetch-records
description: DART·국회·재정·법령·뉴스 등 공개 OpenAPI로 자료를 받아 sources/에 저장할 때 사용한다.
---
# 공개기록 API 수집 절차
1. 대상 소스의 공식 API 문서에서 서비스명·파라미터를 확인한다(검색어·기관·기간).
2. 아래 예시 스크립트를 소스에 맞게 수정해 가상환경 파이썬으로 실행한다: .venv/bin/python .claude/skills/fetch-records/fetch_dart.py (Windows: .venv\Scripts\python ...)
3. 받은 원문(JSON·PDF·XML)을 sources/에 저장하고, 출처를 meta/collection_log.md에 남긴다.
4. 실패·제한(키 오류, 페이월, 열람 제한)은 로그에 기록하고 사람에게 알린다.

이 스킬이 실행하는 예시 스크립트 — .claude/skills/fetch-records/fetch_dart.py (DART 공시 목록):

import os, requests, pathlib, datetime
from dotenv import load_dotenv
load_dotenv()

OUT = pathlib.Path("sources"); OUT.mkdir(exist_ok=True)
META = pathlib.Path("meta"); META.mkdir(exist_ok=True)

# 공시 검색 (정확한 파라미터는 opendart.fss.or.kr API 문서 확인)
params = {
    "crtfc_key": os.environ["DART_API_KEY"],
    "bgn_de": "20260101", "end_de": "20260630",
    "page_count": 20,
}
res = requests.get("https://opendart.fss.or.kr/api/list.json", params=params, timeout=20)
items = res.json().get("list", [])

log = META / "collection_log.md"
with log.open("a", encoding="utf-8") as f:
    for it in items:
        # 필요 시 공시원본(zip)·뷰어 링크를 별도로 받아 sources/에 저장
        f.write(f"- DART | {it.get('corp_name')} | {it.get('report_nm')} | "
                f"{it.get('rcept_no')} | {datetime.date.today()}\n")
        print(it.get("corp_name"), it.get("report_nm"))

---
name: collect-web
description: API가 없거나 로그인·JS가 필요한 웹에서 Playwright MCP나 Scrapling으로 자료를 수집할 때 사용한다.

# 웹 수집 절차
1. 먼저 API가 있는지 확인한다. 있으면 fetch-records 스킬을 쓴다.
2. 로그인·검색폼·페이지네이션이 필요한 페이지는 Playwright MCP로 처리한다.
   - 대상 URL로 이동 → 검색어 입력 → 결과 목록 순회 → 첨부(PDF)·본문 저장.
   - 접근 제한(로그인 벽, 본인확인)은 우회하지 않고 건너뛴다.
3. 안티봇이 있거나 구조가 자주 바뀌는 사이트는 Scrapling으로 받는다(적응형 선택자).
4. 요청 사이에 간격을 두고, robots.txt·약관을 지킨다.
5. 저장한 원문마다 출처(URL·수집일)를 meta/collection_log.md에 남긴다.

7. 윤리와 법 (반드시)

자동 수집은 편하지만 선을 넘기 쉽습니다.

  • 공개기록·공개 API만 다루고, 로그인·본인확인이 필요한 자료(판결서 인터넷열람 등)는 자동 수집하지 않습니다.
  • robots.txt와 사이트 이용약관을 지키고, 요청 사이에 간격을 둬 서버에 부담을 주지 않습니다.
  • 저작권 있는 본문은 수집·저장·인용 범위를 지키고, 개인정보는 최소한만 다룹니다.
  • API 이용약관(호출 한도·재배포 조건)을 지킵니다.
  • 수집은 취재의 출발이며, 사실 확인과 게재 판단·책임은 사람 기자에게 있습니다.

8. 2시간 진행 순서

  • 0부(10분): 왜 API 우선인가 — 수집의 3단(API → 브라우저 → 스크랩)과 법·윤리.
  • 1부(25분): 세팅 — .env(키), Playwright MCP 연결, (선택) Scrapling.
  • 2부(30분): API 수집 — fetch-records로 DART·국회 자료 받기.
  • 3부(30분): 브라우저 수집 — Playwright MCP로 보도자료·검색 페이지 받기.
  • 4부(15분): 안티봇 대응 — Scrapling으로 견고하게 받기(시연).
  • 5부(10분): 탐사 실습 연결 + 윤리 점검.

계획·검토 Shift+Tab 플랜 · /review /plan · /review
권한 승인 프롬프트 샌드박스(read-only / workspace-write / danger-full-access)

바꿀 것은 다음뿐입니다.

  1. CLAUDE.md를 AGENTS.md로 이름만 바꿉니다(내용 그대로).

  2. 서브에이전트(collector)를 .codex/agents/<이름>.toml 로 옮깁니다. 마크다운 프론트매터 대신 TOML 키(name·description·developer_instructions)를 씁니다.

# .codex/agents/collector.toml
name = "collector"
description = "..."            # 기존 description 그대로
developer_instructions = """
... 기존 지침 본문 그대로 ...
"""

  1. 스킬(fetch-records·collect-web)은 SKILL.md 형식이 같습니다. 위치만 Codex 규칙(프로젝트 스킬 또는 ~/.agents/skills/)에 맞추고, 대화에서 $스킬이름으로 부릅니다. MCP가 필요한 스킬은 agents/openai.yaml에 의존성을 선언하면 자동 연결됩니다.

  2. MCP(playwright)는 .mcp.json 대신 ~/.codex/config.toml 에 TOML로 적습니다.

[mcp_servers.playwright]
command = "npx"
args = ["-y", "@playwright/mcp@latest"]

실행은 폴더에서 codex 로 시작하고, 프롬프트(자연어)는 이 문서의 것을 그대로 씁니다.

주의: Codex는 토큰 효율과 터미널 작업에 강하지만, 웹검색이 환경에 따라 약할 수 있습니다. 검색 보완이 부족하면 검색 MCP(Tavily·Brave 등)를 config.toml에 붙이세요. 명령·설정은 자주 바뀌니 codex 안에서 /help로 확인합니다.

도구 명령·API 파라미터·기본 모델은 2026년 6월 기준이며 자주 바뀝니다. 각 포털의 API 문서와 Claude Code의 /help를 먼저 확인하세요.
