문서 더미에서 단서 찾기 — 탐사취재 에이전트

Claude Code의 CLAUDE.md · 서브에이전트 · 스킬 · MCP로 취재 리드 뽑기 (2차 실습)

보관본 안내 — 이 문서는 현행 커리큘럼에 포함되지 않음. 여기 내용은 2차 실습 2막 · 취재의 후반(확인하기)으로 통합됐음. 새로 시작하는 경우 학습 허브 → 1막 · 기획부터 진행할 것. 이 문서는 개체 추출·검증 방법을 따로 참고할 때만 사용.

대상: 1차 바이브 코딩 특강을 들은 기자
도구: Claude Code + 내장 WebSearch (+ 선택: 공개기록 API를 스킬/MCP로)
목표: 공개문서 한 묶음에서 개체(인물·기관·금액·날짜)를 뽑아 공개기록으로 교차검증하고, 관계·타임라인·취재 리드를 담은 HTML 브리프 작성
핵심 원칙: AI는 단서를 모아 주는 도구. 확인과 게재 책임은 사람 기자에게 있음

1. 무엇을 만들고, 무엇을 경험하나

"이 문서들 분석해서 취재 리드 뽑아줘" 한 마디면 다음 순서로 진행됩니다.

sources/ 의 공개문서 (공시 · 판결문 · 예산 · 의안 · 보도자료)
   │
   ▼ 0. PDF 변환       → sources_md/*.md
   │
   ▼ 1. 개체 추출      → output/entities.md         (extractor 서브에이전트 + entity-ledger 스킬)
   │
   ▼ 2. 교차검증       → output/verified.md         (verifier 서브에이전트 + WebSearch)
   │
   ▼ 3. 브리프 작성    → output/investigation_brief.html  (make-brief 스킬: 관계·타임라인·리드)

이 방식은 국제 탐사보도의 표준 형태를 기자 규모로 재현한 것입니다. 대형 문서 유출 조사에서도 "문서를 나눠 개체를 병렬 추출하고, 기자들이 공개기록과 대조해 확인한 뒤, 관계를 지도로 병합"하는 흐름을 씁니다. 우리는 그 축소판을 Claude Code로 만듭니다.

경험하는 네 기능은 다음과 같습니다.

  • CLAUDE.md: 취재 규칙(개체·출처 명기, 근거 없는 관계 금지)과 작업 순서를 담아 매번 자동 적용합니다.
  • 서브에이전트(2개): 추출과 검증을 각각 독립된 문맥에서 처리합니다. 특히 검증자가 추출자의 판단에 오염되지 않는 점이 중요합니다.
  • 스킬(3개): PDF 변환·개체 대장 작성·HTML 브리프의 표준 절차를 담아 자동 적용합니다.
  • MCP·도구: 교차검증은 내장 WebSearch로 하고, 필요하면 DART·빅카인즈 같은 공개기록 API를 스킬이나 MCP로 붙입니다.

2. 폴더 구조

agent_investigation/
├── CLAUDE.md           # 취재 규칙 + 작업 파이프라인 + 윤리
├── sources/            # 원본 공개문서 (PDF/txt)
├── sources_md/         # 변환된 마크다운 (추출 기준)
├── output/             # 개체 대장 · 검증 · HTML 브리프
└── .claude/
    ├── agents/
    │   ├── extractor.md          # 서브에이전트: 개체 추출
    │   └── verifier.md           # 서브에이전트: 교차검증
    └── skills/
        ├── pdf-to-md/SKILL.md    # 스킬: PDF 변환 (1차 실습 재사용)
        ├── pdf-to-md/convert.py
        ├── entity-ledger/SKILL.md # 스킬: 개체 대장 작성
        └── make-brief/SKILL.md    # 스킬: HTML 브리프

3. 준비

3-1. Claude Code 실행

mkdir agent_investigation && cd agent_investigation
claude

3-2. 실습용 공개문서 준비

법적·윤리 위험을 피하기 위해 실제 제보·유출 문서가 아니라 공개기록으로 실습합니다. 하나의 사안(예: 특정 예산 사업, 특정 기관의 계약)을 정해 관련 문서 20~30건을 sources/에 모읍니다.

  • 기업 공시: DART 전자공시(dart.fss.or.kr)
  • 국회 의안·회의록: 의안정보시스템(likms.assembly.go.kr)
  • 판결문: 판결서 인터넷열람
  • 예산·재정: 열린재정, 지자체 예산서
  • 보도자료: 각 부처·기관 공개 자료

같은 사안을 다룬 문서일수록 개체가 반복 등장해 관계·리드가 잘 드러납니다.

3-3. PDF 변환 도구 (1차 실습과 동일)

PDF의 표·수치·스캔까지 살리려면 pymupdf4llm으로 변환. 가상환경(.venv)을 활성화한 상태에서 pip로 설치.

python -m venv .venv
.venv\Scripts\Activate.ps1        # macOS: source .venv/bin/activate
pip install pymupdf pymupdf4llm

설치가 막히면 Claude Code에 "내 OS에 맞게 .venv를 만들고 pymupdf4llm을 설치해줘"라고 요청. 자세한 절차는 입문 가이드 사전 준비 2.

4. 설정 파일 만들기

아래 내용을 그대로 저장합니다. (Claude Code 안에서 "아래 내용으로 OO 파일을 만들어 줘"라고 시켜도 됩니다.)

4-1. CLAUDE.md

# 문서 더미 탐사취재 프로젝트 규칙

## 역할과 원칙
- 너는 탐사취재 보조다. 최종 판단과 게재 책임은 사람 기자에게 있다.
- 개체(인물·기관·기업·금액·날짜)와 사실은 지어내지 않는다. 문서에 없으면 비운다.
- 개체 간 '관계'는 근거(같은 문서·같은 계약 등)가 있을 때만 적고, 그 근거를 함께 남긴다.
- 모든 항목에 출처(문서명·페이지 또는 URL)를 단다. 근거가 없으면 [확인 필요].
- 모든 설명은 한국어로 한다.

## 입력/출력
- 원본 문서: sources/  (공개기록: 공시·판결문·예산·의안·보도자료 등)
- 변환본(추출 기준): sources_md/
- 산출물: output/

## 작업 파이프라인 ("문서 분석해서 취재 리드 뽑아줘"라고 하면 이 순서로)
0. pdf-to-md 스킬로 sources/의 PDF를 sources_md/로 변환한다.
1. extractor 서브에이전트 + entity-ledger 스킬로 개체 대장을 만든다. → output/entities.md
2. verifier 서브에이전트로 반복 등장·이상 신호 개체를 공개기록과 교차검증한다. → output/verified.md
3. make-brief 스킬로 관계·타임라인·취재 리드를 담은 HTML 브리프를 만든다. → output/investigation_brief.html
각 단계 결과는 output/에 파일로 남기고, 단계마다 무엇을 했는지 한 줄로 보고한다.

## 취재 윤리 (반드시 지킨다)
- 공개기록만 다룬다. 개인 사생활·미확인 혐의를 단정하지 않는다.
- AI가 뽑은 개체·관계는 '단서'일 뿐이다. 게재 전 사람이 원문·1차 출처로 확인한다.
- 명예훼손·프라이버시 위험이 있으면 멈추고 사람에게 알린다.

## 금지
- 없는 개체, 허위 관계, 추측한 금액·날짜, 출처 없는 단정.

4-2. 서브에이전트 — .claude/agents/extractor.md

---
name: extractor
description: sources_md/의 문서에서 인물·기관·기업·금액·날짜·계약 등 개체를 빠짐없이 추출할 때 사용.
tools: Read, Grep, Glob
model: sonnet
---
너는 문서 추출 담당이다. 주어진 문서에서 다음 개체를 뽑는다.
- 인물, 기관/부서, 기업/단체, 금액(단위·기간 명시), 날짜, 계약·사업명, 직위.
- 각 개체가 '어느 문서 몇 페이지'에 나오는지 위치를 반드시 적는다.
- 문서에 없는 것은 만들지 않는다. 애매하면 비운다.
결과는 개체별 한 행의 표로 정리해 돌려준다. HTML은 만들지 않는다(메인 세션 몫).

4-3. 서브에이전트 — .claude/agents/verifier.md

---
name: verifier
description: 개체 대장에서 반복 등장·이상 신호 개체를 공개기록과 웹으로 교차검증할 때 사용.
tools: Read, Grep, WebSearch, WebFetch
model: opus
---
너는 교차검증 담당이다. 개체 대장에서 여러 문서에 반복 등장하거나 이상 신호(큰 금액, 반복 계약 등)가 있는 개체를 골라 확인한다.
- WebSearch로 공식·1차 출처(정부·공시·법원·기관)를 우선 찾고 WebFetch로 확인한다.
- 확인 결과에 URL과 확인 날짜를 단다. 확인 안 되면 [미확인]으로 남긴다.
- 문서 내용과 공개기록이 상충하면 표시한다. 추측으로 메우지 않는다.
- '확인된 사실'만 보고한다. 혐의를 단정하지 않는다.

두 서브에이전트를 나눈 이유는, 추출(문서 안)과 검증(문서 밖 공개기록)을 독립된 문맥에서 처리해 서로 오염되지 않게 하기 위함입니다.

4-4. 스킬 — .claude/skills/pdf-to-md/SKILL.md

---
name: pdf-to-md
description: sources/의 PDF를 표·다단·스캔까지 살려 마크다운으로 변환할 때 사용한다.
---
# PDF → 마크다운 변환 절차
1. sources/의 모든 PDF를 sources_md/ 에 .md로 변환한다.
   python .claude/skills/pdf-to-md/convert.py     (.venv 활성화 상태에서)
2. 내용이 비어 있는 파일은 스캔본일 수 있으니 사람에게 알린다.
3. 표는 파이프(|) 마크다운으로 변환된다. 핵심 수치는 원본 PDF 페이지와 교차 확인한다.

.claude/skills/pdf-to-md/convert.py

import pathlib
import pymupdf4llm

SRC = pathlib.Path("sources")
OUT = pathlib.Path("sources_md")
OUT.mkdir(exist_ok=True)

for pdf in sorted(SRC.glob("*.pdf")):
    md = pymupdf4llm.to_markdown(str(pdf))   # 다단·표 살리고 필요 시 자동 OCR
    target = OUT / (pdf.stem + ".md")
    target.write_text(md, encoding="utf-8")
    status = "OK" if md.strip() else "빈 결과(스캔본일 수 있음)"
    print(pdf.name, "->", target.name, "[", status, "]")

4-5. 스킬 — .claude/skills/entity-ledger/SKILL.md

---
name: entity-ledger
description: 문서 더미에서 개체를 뽑아 '개체 대장'을 만들 때 사용한다.
---
# 개체 대장(entity ledger) 작성 절차
1. sources_md/의 모든 문서를 읽는다. 문서가 많으면 extractor 서브에이전트에 나눠 맡긴다.
2. 개체를 아래 표에 한 행씩, id를 붙여 정리한다.

| id | 개체 | 유형(인물/기관/기업/금액/날짜/계약) | 값·상세 | 등장 문서·페이지 | 등장 횟수 |
|----|------|------|------|------|------|

3. 같은 개체가 여러 문서에 나오면 한 행으로 합치고 등장 위치를 모두 적는다.
4. 2회 이상 반복 등장하거나 큰 금액·이상 신호가 있는 개체는 '주목'으로 표시한다.
5. output/entities.md 로 저장한다.

4-6. 스킬 — .claude/skills/make-brief/SKILL.md

---
name: make-brief
description: 개체 대장과 검증 결과로 관계·타임라인·취재 리드를 담은 HTML 브리프를 만들 때 사용한다.
---
# 탐사 브리프(HTML) 작성 절차
1. 입력은 output/entities.md 와 output/verified.md 다. 여기 있는 사실만 쓴다.
2. 다음을 구성한다.
   - 주목 개체표: 반복 등장·이상 신호 개체와 등장 문서·검증 상태.
   - 관계: 같은 문서·같은 계약에 함께 나온 개체 묶음(근거 문서 표기). 근거 없으면 쓰지 않는다.
   - 타임라인: 날짜가 있는 사건을 시간순으로.
   - 취재 리드 3~5개: "무엇을 왜 더 확인해야 하나"를 질문 형태로, 근거(문서·URL)와 함께. 단정 금지.
3. 모든 항목에 출처 링크(문서·페이지 또는 URL)를 단다. CSS는 파일 안에 인라인으로.
4. 상단에 문서 건수·개체 수·작성일. 하단에 "AI가 뽑은 단서이며 게재 전 사람이 1차 출처로 확인해야 함" 고지.
5. output/investigation_brief.html 한 파일로 저장한다.

5. 실행

준비가 끝나면 한 마디면 됩니다.

sources 폴더의 공개문서를 분석해 취재 리드를 뽑아줘. CLAUDE.md 파이프라인대로
PDF 변환 → 개체 대장 → 교차검증 → HTML 브리프까지 진행하고, 단계마다 한 줄로 보고해.

기능을 하나씩 체감하고 싶을 때는 단계를 끊어서 시키면 됩니다.

extractor 서브에이전트와 entity-ledger 스킬로 개체 대장을 만들어 output/entities.md 로 저장해.

verifier 서브에이전트로 반복 등장하는 개체를 공개기록과 교차검증해서 output/verified.md 로 정리해.

make-brief 스킬로 관계·타임라인·취재 리드를 담은 HTML 브리프를 만들어줘.

큰 작업 전에 Shift+Tab으로 플랜 모드에 들어가면, 어떤 서브에이전트·스킬이 언제 작동하는지 계획으로 먼저 보여 줍니다.

6. 한 걸음 더 — 공개기록 API 붙이기 (심화)

교차검증은 내장 WebSearch로 충분하지만, 정밀도를 높이려면 공개기록 API를 붙일 수 있습니다.

  • 뉴스 대조: 빅카인즈(BIGKINDS-LAB) REST API로 개체가 언론에 언제·어떻게 등장했는지 확인.
  • 기업 확인: DART 전자공시 OpenAPI로 회사·임원·계약 정보를 확인.

붙이는 방법은 둘 중 하나입니다. ① 작은 스킬로 감싸기(Bash에서 API를 호출하는 스크립트) 또는 ② MCP 서버로 등록하기(claude mcp add). 검색 MCP를 여러 개 깔면 혼란이 오니, 필요한 것 하나만 붙이는 것을 권합니다.

7. 검증과 윤리 (가장 중요)

이 실습은 취재의 '출발점'을 자동화할 뿐, 결론을 내리지 않습니다.

  • AI가 뽑은 개체·관계·리드는 모두 '단서'입니다. 게재 전 사람이 원문과 1차 출처로 반드시 확인합니다.
  • 개체와 관계는 환각(없는 인물, 없는 연결)이 생길 수 있습니다. 근거 문서가 없는 관계는 버립니다.
  • 공개기록만 다루고, 미확인 혐의를 단정하지 않습니다. 명예훼손·프라이버시 위험이 있으면 멈춥니다.
  • AI 보조로 작성했다는 사실을 밝히고, 최종 책임은 사람에게 있음을 잊지 않습니다.

8. 2시간 진행 순서

  • 0부(10분): 왜 이 방식인가 — 취재는 쓰기가 아니라 찾기·확인. 국제 탐사보도의 "추출 → 교차확인 → 관계 병합" 소개.
  • 1부(20분): 프로젝트 세팅 — CLAUDE.md, 서브에이전트 2개, 스킬 3개.
  • 2부(30분): 개체 추출(팬아웃) — sources_md의 문서에서 개체 대장 작성.
  • 3부(25분): 교차검증 — 반복 등장·이상 신호 개체를 공개기록과 대조.
  • 4부(25분): 관계·타임라인·리드 — HTML 브리프 생성.
  • 5부(10분): 검증·윤리 — 사람 확인, 명예훼손·프라이버시.

Codex로 만들기

이 실습은 Claude Code 기준이지만 OpenAI Codex로도 거의 그대로 만들 수 있습니다. 개념이 1:1로 대응되고, 파일 이름·형식과 실행 명령만 다릅니다.

개념 Claude Code OpenAI Codex
프로젝트 지침 CLAUDE.md AGENTS.md (내용 동일)
스킬 .claude/skills/<이름>/SKILL.md SKILL.md (자동 로드, 호출은 $이름)
서브에이전트 .claude/agents/<이름>.md .codex/agents/<이름>.toml
MCP 연결 .mcp.json ~/.codex/config.toml 의 [mcp_servers]
실행 claude codex
계획·검토 Shift+Tab 플랜 · /review /plan · /review
권한 승인 프롬프트 샌드박스(read-only / workspace-write / danger-full-access)

바꿀 것은 다음뿐입니다.

  1. CLAUDE.md를 AGENTS.md로 이름만 바꿉니다(내용 그대로).

  2. 서브에이전트(extractor·verifier)를 .codex/agents/<이름>.toml 로 옮깁니다. 마크다운 프론트매터 대신 TOML 키(name·description·developer_instructions)를 씁니다.

# .codex/agents/verifier.toml
name = "verifier"
description = "..."            # 기존 description 그대로
developer_instructions = """
... 기존 지침 본문 그대로 ...
"""

  1. 스킬(pdf-to-md·entity-ledger·make-brief)은 SKILL.md 형식이 같습니다. 위치만 Codex 규칙(프로젝트 스킬 또는 ~/.agents/skills/)에 맞추고, 대화에서 $스킬이름으로 부릅니다. MCP가 필요한 스킬은 agents/openai.yaml에 의존성을 선언하면 자동 연결됩니다.

  2. (심화) 공개기록 MCP를 붙일 때는 .mcp.json 대신 ~/.codex/config.toml 의 [mcp_servers]에 TOML로 등록합니다.

실행은 폴더에서 codex 로 시작하고, 프롬프트(자연어)는 이 문서의 것을 그대로 씁니다.

주의: Codex는 토큰 효율과 터미널 작업에 강하지만, 웹검색이 환경에 따라 약할 수 있습니다. 검색 보완이 부족하면 검색 MCP(Tavily·Brave 등)를 config.toml에 붙이세요. 명령·설정은 자주 바뀌니 codex 안에서 /help로 확인합니다.
