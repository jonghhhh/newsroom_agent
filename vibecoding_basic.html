사전 준비 1. 파이썬(Python) 설치

바이브 코딩으로 만든 프로그램을 실행하거나 데이터를 다루려면 파이썬이 필요함. 강의 시작 전 설치 권장. (VS Code·Node.js 설치는 1부에서 이어짐)

  1. 브라우저에서 python.org 접속 → 상단 Downloads.
  2. 내 컴퓨터에 맞는 버전 내려받기.
    • Windows: 노란 버튼 "Download Python 3.x.x" 클릭. 설치 첫 화면에서 "Add python.exe to PATH" 체크 필수 → "Install Now".
    • macOS: "macOS 64-bit universal2 installer" 내려받아 실행.
    • 32/64비트 확인법: (Windows) 설정 → 시스템 → 정보 → "시스템 종류". 요즘 컴퓨터는 대부분 64비트.
  3. 설치 확인 — 터미널에 입력.
python --version
  • macOS는 python3 --version으로 확인. Python 3.x.x처럼 버전이 보이면 완료.
  • 권장 버전: 3.11 이상.

"Add to PATH"를 빠뜨린 경우 — 터미널에서 python을 못 찾음. 설치 파일을 다시 실행해 "Modify" → PATH 추가.

사전 준비 2. 가상환경(.venv)과 pip

파이썬 자체 설치는 절반. 나머지 절반은 패키지를 어디에 설치할지 정하는 일임. 이 절만 익히면 2차 실습(취재보도)의 설치 관련 사고가 거의 사라짐.

2-1. 왜 가상환경을 쓰나

  • 문제: 패키지를 컴퓨터 전체에 설치하면 프로젝트끼리 버전이 충돌함. A 프로젝트는 requests 2.28이 필요한데 B 프로젝트가 2.32로 덮어쓰는 식.
  • 비유: 가상환경 = 프로젝트 전용 서랍. 서랍 안에만 물건을 넣으니 다른 프로젝트와 섞이지 않음. 프로젝트를 지울 때 서랍째 버리면 끝.
  • 결과: "내 컴퓨터에선 되는데" 문제가 크게 줄어듦.
  • 이 강의의 표준: 파이썬 기본 기능인 venv + pip. 추가로 배울 도구 없음.

이름은 왜 .venv인가 — 관례임. 점(.)으로 시작해 숨김 폴더가 되고, VS Code·깃 등 대부분의 도구가 이 이름을 자동 인식함. 다른 이름도 되지만 굳이 바꿀 이유 없음.

2-2. 만들기 · 켜기 · 끄기

① 작업 폴더로 이동 — 가상환경은 프로젝트 폴더 안에 만듦.

cd my-first-vibe

② 가상환경 만들기 — 폴더 안에 .venv/가 생김. 한 프로젝트에 한 번만 실행.

# Windows
python -m venv .venv

# macOS / Linux
python3 -m venv .venv

③ 활성화(켜기) — 터미널을 새로 열 때마다 필요함.

# Windows · PowerShell (VS Code 기본 터미널)
.venv\Scripts\Activate.ps1

# Windows · 명령 프롬프트(cmd)
.venv\Scripts\activate.bat

# macOS / Linux
source .venv/bin/activate

④ 켜졌는지 확인 — 터미널 입력줄 맨 앞에 (.venv)가 붙으면 성공.

(.venv) PS C:\vscode\my-first-vibe>
 ↑ 이 표시가 핵심

⑤ 끄기 — 다른 프로젝트로 옮길 때.

deactivate

2-3. pip로 패키지 설치하기

반드시 (.venv)가 켜진 상태에서 설치. 그래야 서랍 안으로 들어감.

pip install requests python-dotenv
명령하는 일
pip install 패키지명패키지 설치
pip list지금 서랍에 뭐가 들었는지 확인
pip freeze > requirements.txt설치 목록을 파일로 저장(버전까지 고정)
pip install -r requirements.txt저장된 목록 그대로 재설치. 다른 컴퓨터에서 똑같은 환경 복원
pip install --upgrade 패키지명최신 버전으로 올리기

실행 — 활성화 상태에서 그냥 python.

python wordcount.py

공유·백업 규칙 — .venv/ 폴더는 공유하지 않음(용량이 크고 OS마다 내용이 다름). 대신 requirements.txt만 공유. .gitignore에 .venv/와 .env를 넣어 둘 것.

2-4. VS Code에 가상환경 연결

VS Code가 어느 파이썬을 쓸지 알려 줘야 자동완성·오류표시가 맞게 동작함.

  1. VS Code 확장 탭에서 Python 확장(제작사 Microsoft) 설치.
  2. Ctrl+Shift+P(macOS는 Cmd+Shift+P) → Python: Select Interpreter 입력.
  3. 목록에서 .venv가 붙은 항목 선택. 보통 ('.venv': venv)로 표시됨.
  4. 이후 VS Code 터미널을 새로 열면 (.venv)가 자동으로 켜짐.

2-5. 가상환경에서 자주 나는 오류

증상원인과 해결
PowerShell에서 이 시스템에서 스크립트를 실행할 수 없으므로… Windows 스크립트 실행 정책 때문. 아래 명령 한 번 실행 후 다시 활성화 (뒤에 코드 블록 있음)
ModuleNotFoundError: No module named 'requests' 설치는 했는데 활성화를 안 한 상태로 실행한 경우가 대부분. (.venv) 표시부터 확인
pip: command not found 파이썬 미설치 또는 PATH 누락. python -m pip install ...로 우회 가능
설치했는데 VS Code가 빨간 줄로 표시 인터프리터 미선택. 2-4 절 다시 수행
폴더를 옮겼더니 활성화가 안 됨 .venv는 경로를 기억함. .venv 폴더를 지우고 2-2부터 다시 실행 
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

막히면 AI에게 그대로 물어볼 것 — 오류 메시지를 복사해 붙이고 "내 OS는 Windows야. 이 오류 원인과 해결 방법 알려줘"라고 요청. 설치 문제는 AI가 가장 잘 해결하는 영역임.

0부. 바이브 코딩이란?

0-1. 한 문장 정의

바이브 코딩(Vibe Coding) = 프로그래밍 언어 대신 자연어(우리말)로 AI에게 시켜 소프트웨어를 만드는 방식.

  • for문을 외울 필요 없음. "할 일을 추가·삭제할 수 있는 웹페이지 만들어 줘"라고 말로 요청하면 AI가 코드를 씀.
  • 사람의 일은 결과를 보고 "이렇게 고쳐 줘"라고 대화하며 완성도를 높이는 것.

0-2. 초보가 꼭 기억할 3가지

  1. 나는 감독, AI는 배우 — 코드를 한 줄씩 쓰는 사람이 아니라 무엇을 만들지 결정하고 검수하는 사람.
  2. 작게, 한 번에 한 단계 — "쇼핑몰 만들어 줘"보다 "할 일을 입력하는 칸 하나 만들어 줘"가 훨씬 잘 됨.
  3. AI는 가끔 틀림(할루시네이션) — 그럴듯하지만 틀린 답이 나옴. 실행해 보고 확인하는 습관이 핵심.

0-3. 사용할 도구 (한 가지만 골라도 됨)

도구 만든 곳 이 강의에서 쓰는 모델 (2026.8) 핵심 한 줄
Claude Code Anthropic Claude Opus 5 (기본) 코딩 특화. 평이 가장 좋고 문서가 많아 따라 하기 쉬움
OpenAI Codex OpenAI GPT-5.5 (기본), GPT-5.3-Codex 대화에 강하고 무난. 국내 이용자 수가 가장 많음
Antigravity CLI Google Gemini 3.5 Flash(기본), Gemini 3.1 Pro 구 Gemini CLI의 후속. 검색 근거 활용에 강함

세 도구 모두 "에이전트형 CLI" — 코드를 추천만 하는 게 아니라 파일을 직접 만들고 고치고 명령어까지 실행함. 그래서 항상 "실행해도 될까요?"라고 묻고, 사람이 내용을 보고 승인하는 절차를 거침.

실습은 하나만 골라도 충분 — 셋의 사용법이 거의 같음. 이 문서는 세 가지를 모두 다루지만, 강의에서는 본인이 결제·계정을 가진 하나로 끝까지 진행하면 됨. 수강생 중 Codex 이용자가 많다면 마지막 절 Codex로 대체하기부터 봐도 무방.

1부. 공통 준비 — 모든 도구의 출발선

세 도구 모두 ① VS Code(편집기) + ② 터미널 + ③ Node.js 위에서 돌아감. 이 셋만 깔면 나머지는 거의 동일.

1-1. VS Code 설치 (편집기)

  1. 브라우저에서 code.visualstudio.com 접속 → Download.
  2. 설치 후 실행. 한글 메뉴를 원하면 확장 탭에서 Korean Language Pack 설치.

1-2. 터미널 열기 (AI에게 말 거는 창구)

  • VS Code 상단 메뉴 → Terminal → New Terminal. 단축키는 Ctrl + 백틱(`).
  • 화면 아래쪽에 까만 입력창이 나타나면 성공. 앞으로 여기에 명령어를 입력함.

1-3. Node.js 설치 (엔진)

Claude Code와 Codex는 설치에 npm(Node.js에 포함)을 씀.

  1. nodejs.org 접속 → LTS 버전 다운로드·설치.
  2. 설치 확인 — 터미널에 입력.
node -v
npm -v

v22.x.x처럼 버전 번호가 나오면 준비 끝.

macOS: Homebrew가 있으면 brew install node 한 줄로 끝.
Windows: 설치 중 "Add to PATH" 체크 유지.
Antigravity CLI: 단일 실행파일이라 Node.js 없이도 설치됨(4부 참고).

1-4. 작업 폴더 만들기 (집 짓기 전 땅 고르기)

원하는 위치에 빈 폴더를 만들고 VS Code에서 File → Open Folder로 엶.

# 터미널에서 직접 만들어도 됨
mkdir my-first-vibe
cd my-first-vibe

파이썬을 쓸 계획이면 여기서 사전 준비 2의 가상환경까지 만들어 두면 좋음.

1-5. 공통 실습 과제

"오늘의 할 일(To-Do) 웹앱"
할 일을 입력해 추가하고, 완료하면 체크하고, 삭제할 수 있는 한 페이지짜리 웹앱. 별도 설치 없이 브라우저로 바로 열 수 있게 HTML 파일 하나로 제작.

2·3·4부에서 같은 과제를 도구만 바꿔 만들어 봄. 결과물이 어떻게 다른지 비교하는 것이 목적.

2부. Claude Code 실습 — 가장 쉬운 출발점

이 부분은 조태호 저 『혼자 공부하는 바이브코딩 with 클로드코드』(한빛미디어)를 참조함. 더 깊이 배우려면 책과 공식 깃허브(참고문헌 [1]) 추천.

2-1. Claude Code란

  • Anthropic이 만든 터미널 기반 AI 코딩 에이전트.
  • 2026년 8월 기준 기본 모델은 Claude Opus 5. 더 빠른 작업엔 Sonnet 5, 가벼운 작업엔 Haiku 4.5 선택 가능.
  • 모델 변경은 /model, 생각의 깊이 조절은 /effort.

2-2. 설치 (택1)

방법 A — npm (모든 OS 공통, 권장)

npm install -g @anthropic-ai/claude-code

방법 B — 네이티브 설치 프로그램

  • macOS/Linux: curl -fsSL https://claude.ai/install.sh | bash
  • Windows: 공식 문서의 WinGet/CMD 방법 참고 (참고문헌 [2])

설치 확인:

claude --version

2-3. 실행과 로그인

작업 폴더 안에서:

claude
  • 처음 실행하면 브라우저가 열리며 Anthropic 계정 로그인 요청.
  • 구독: Pro 약 $20 / Max $100·$200. 사용량에 따라 선택.

VS Code 안에서 쓰기 — 확장 탭에서 "Claude Code for VS Code"(제작사 anthropic) 설치 → 사이드 패널에서 인라인 diff(바뀐 부분 미리보기), @파일명 멘션, /model·/context 슬래시 명령을 GUI로 사용 가능.

2-4. 첫 실습 — 할 일 웹앱 만들기

claude가 실행된 상태에서 우리말로 그대로 입력.

초보자도 이해하기 쉽게, 할 일을 추가·완료체크·삭제할 수 있는 '오늘의 할 일' 웹앱을 만들어 줘.
조건:
1) 설치 없이 브라우저로 바로 열리도록 index.html 파일 하나로 만들 것
2) 디자인은 깔끔하고 모바일에서도 보기 좋게
3) 할 일 목록은 새로고침해도 남아 있도록 브라우저에 저장

Claude Code는 계획을 먼저 보여주고, 동의하면 index.html을 생성함. 파일이 생기면 더블클릭하거나 아래 명령으로 엶.

# macOS
open index.html
# Windows
start index.html

나올 결과물의 뼈대 예시. 이런 코드가 나오는지 눈으로 확인하는 용도.

<!DOCTYPE html>
<html lang="ko">

    body { font-family: sans-serif; max-width: 480px; margin: 40px auto; padding: 0 16px; }

  </style>
</head>
<body>
  <h1>오늘의 할 일</h1>
  <input id="todoInput" placeholder="할 일을 입력하세요" />
  <button onclick="addTodo()">추가</button>
  <ul id="todoList"></ul>
  <script>
    // 브라우저 저장소(localStorage)에서 목록 불러오기
    let todos = JSON.parse(localStorage.getItem('todos') || '[]');
    function save() { localStorage.setItem('todos', JSON.stringify(todos)); render(); }
    function addTodo() {
      const v = document.getElementById('todoInput').value.trim();
      if (!v) return;
      todos.push({ text: v, done: false });
      document.getElementById('todoInput').value = '';
      save();
    }
    function render() {
      const ul = document.getElementById('todoList');
      ul.innerHTML = '';
      todos.forEach((t, i) => {
        const li = document.createElement('li');
        li.innerHTML = `<span class="${t.done ? 'done' : ''}"
          onclick="toggle(${i})">${t.text}</span>
          <button onclick="remove(${i})">삭제</button>`;
        ul.appendChild(li);
      });
    }
    function toggle(i) { todos[i].done = !todos[i].done; save(); }
    function remove(i) { todos.splice(i, 1); save(); }
    render();
  </script>
</body>
</html>

2-5. 대화로 고치기 (바이브 코딩의 핵심)

결과를 보고 말로 수정 요청.

완료한 항목이 자동으로 목록 맨 아래로 내려가게 해 줘. 그리고 상단에 '남은 할 일 N개'를 표시해 줘.

다크 모드 켜고 끄는 버튼을 오른쪽 위에 추가해 줘.

2-6. 두 번째 실습 — 파이썬 프로그램 만들고 실행하기

웹페이지(HTML)는 브라우저로 열어 봤음. 이번에는 터미널에서 돌아가는 작은 파이썬 프로그램을 만들어, AI가 코드를 쓰고 직접 실행해 결과까지 보여주는 경험을 함.

먼저 가상환경 활성화 — 사전 준비 2대로 (.venv)가 켜진 상태에서 진행.

claude 실행 상태에서 우리말로 요청.

글을 분석해 글자 수·단어 수·문장 수를 세어 주는 간단한 파이썬 프로그램을 만들어 줘.
조건:
1) 파일 이름은 wordcount.py
2) 분석할 예시 글을 코드 안에 넣어 두고, 결과를 보기 좋게 출력
3) 초보가 읽기 쉽게 한국어 주석을 충분히 달 것
4) 표준 라이브러리만 사용(추가 설치 없이 실행되게)
그리고 그 프로그램을 실행해서 결과까지 보여줘.

Claude가 wordcount.py를 만들고 직접 실행해 결과를 보여줌. 만들어질 코드의 예시:

# 분석할 글 (이 부분만 바꾸면 다른 글도 분석됨)
text = "오늘 시청에서 기자회견이 열렸다. 시장은 내년 예산을 발표했다. 질문도 이어졌다."

# 글자 수 (공백 포함 / 공백 제외)
char_with_space = len(text)
char_no_space = len(text.replace(" ", ""))

# 단어 수 (공백 기준으로 나눠 센다)
word_count = len(text.split())

# 문장 수 (마침표·물음표·느낌표 개수로 단순 계산)
sentence_count = text.count(".") + text.count("?") + text.count("!")

print("글자 수(공백 포함):", char_with_space)
print("글자 수(공백 제외):", char_no_space)
print("단어 수:", word_count)
print("문장 수:", sentence_count)

직접 실행해 보려면 터미널에 입력.

python wordcount.py

외부 패키지가 필요한 프로그램이라면 — (.venv)가 켜진 상태에서 pip install로 먼저 설치. AI에게 "필요한 패키지를 pip install로 설치하고 requirements.txt에도 추가해줘"라고 요청하면 한 번에 처리됨.

웹앱 때와 똑같이, 결과를 보고 말로 고치면 됨.

평균 문장 길이(공백 제외 글자 수 ÷ 문장 수)도 함께 출력해 줘.

HTML(웹페이지)과 파이썬(프로그램) 두 가지를 만들어 보면, 바이브 코딩이 웹뿐 아니라 일반 프로그램에도 똑같이 통한다는 걸 알 수 있음.

2-7. CLAUDE.md — 프로젝트에 규칙 심기

폴더에 CLAUDE.md 파일을 두면 Claude가 매번 그 규칙을 자동으로 읽음. 초보에게 특히 강력한 기능.

# 프로젝트 규칙
- 모든 설명과 주석은 한국어로 작성한다.
- 초보자가 읽기 쉽게 변수명은 명확하게 짓는다.
- 외부 라이브러리는 꼭 필요할 때만 쓴다.
- 파이썬 패키지는 .venv 가상환경에 pip로 설치한다. 설치 후 requirements.txt를 갱신한다.

2부 요약: 설치 → claude 실행 → 우리말로 요청 → 결과 확인 → 대화로 수정 → CLAUDE.md로 규칙화. 웹앱이든 파이썬 프로그램이든 같은 사이클이며, 이것이 바이브 코딩의 전부.

5-2. 어떤 도구든 통하는 원칙 5가지

  1. 작게 쪼개서 시킬 것 — "앱 전체"가 아니라 "기능 하나"씩.
  2. 조건을 구체적으로 적을 것 — 파일 형식, 디자인, 저장 방식까지 명시.
  3. 계획을 먼저 보고 승인할 것 — 실행 전 무엇을 할지 확인.
  4. 항상 실행해서 확인할 것 — AI는 틀릴 수 있음.
  5. 규칙은 .md 파일로 고정할 것 — CLAUDE.md / AGENTS.md / GEMINI.md.
