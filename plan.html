1막 · 기획 — 배경 파악부터 질문 목록까지

과거 기사 수집 · 배경 요약 · 취재 계획을 스킬로 한 번에

대상: 1차 특강(입문·심화)을 들은 기자 — 2차 실습의 첫 회차 (2시간)
도구: Claude Code + 네이버 뉴스 검색 API(과거 기사) + 내장 WebSearch(웹 배경)
목표: 취재 주제 한 마디로 배경을 논리적으로 요약하고, 2막에서 답을 찾아야 할 질문 목록 Q1·Q2·Q3…가 담긴 취재 계획 작성
핵심 원칙: 기사 전문은 복제하지 않고 링크로. 취재 계획은 초안이며 판단·섭외·게재는 사람 기자의 몫

1. 무엇을 만들고, 무엇을 경험하나

"이 주제 취재 기획해줘" 한 마디면 다음 순서로 진행됩니다.

"<취재 주제>"
   │
   ▼ 1. 과거 기사 수집   네이버 뉴스 API로 기사 메타·링크 (news-archivist 서브에이전트)
   │
   ▼ 2. 웹 배경 보완     정의·연혁·통계·해외 사례·핵심 문서 (web-researcher 서브에이전트)
   │
   ▼ 3. 배경 요약·구성   타임라인·인물/기관·쟁점·언론사 프레임 (background-brief 스킬)
   │
   ▼ 4. 취재 계획 설계   핵심 질문·필요 자료·인터뷰 대상·현장 취재 (reporting-plan 스킬)
   │
   ▼ 1_plan/reporting_plan.md   ← 2막의 입력이 되는 파일

스킬을 '모드'처럼 씀. 수집은 서브에이전트가, 요약과 계획은 각각의 스킬이 맡아 필요하면 한 단계만 따로 실행 가능.

1-1. 이 회차의 진짜 산출물은 '질문 목록'

취재 계획 문서는 읽고 끝나는 보고서가 아님. 이 회차가 만들어야 할 핵심은 번호가 붙은 질문 목록임.

Q1  해상풍력 인허가에 평균 몇 개월이 걸리고, 가장 오래 걸린 사업은 무엇인가?
Q2  특별법 통과 전후로 특정 사업자의 수주가 늘었는가?
Q3  국산화율 목표치는 누가 정했고, 실제 달성률은 얼마인가?
...

번호를 붙이는 이유는 추적. 2막에서 모은 자료는 "어느 질문에 답하려고 가져온 것"인지 Q번호로 묶이고, 3막의 기사 문장은 그 사슬을 거슬러 올라가 원문 몇 쪽까지 되짚힘. 이 번호가 세 회차를 하나로 잇는 고리임.

따라서 질문은 공개기록으로 확인 가능한 형태여야 함.

  • 좋음: "인허가에 평균 몇 개월 걸렸나?" → 인허가 대장·보도자료로 답이 나옴.
  • 나쁨: "해상풍력은 바람직한가?" → 자료로 답이 안 나옴. 취재 계획에 넣지 않음.

이 회차에서 경험하는 네 기능:

  • CLAUDE.md: 취재 규칙(출처 명기, 기사 전문 복제 금지, 추측 금지)과 작업 순서를 담아 자동 적용. 여기서 한 번 만들면 2·3막에서 그대로 사용.
  • 서브에이전트(2개): 뉴스 아카이브 수집과 웹 배경을 각각 독립 문맥에서 처리.
  • 스킬(3개): 수집 스크립트, 배경 요약·논리 구성, 취재 계획 설계의 표준 절차.
  • API: 과거 기사는 네이버 뉴스 검색 API, 웹 배경은 내장 WebSearch.

3. 준비

3-1. 폴더 만들고 Claude Code 실행

이 폴더는 세 회차 내내 사용. 이름을 바꾸거나 지우지 말 것.

mkdir newsroom_agent && cd newsroom_agent
claude

3-2. 파이썬 환경 (.venv + pip)

API 호출에 파이썬을 씀. 세 회차 모두 파이썬 기본 기능인 venv + pip로 통일. 새로 배울 도구 없음.

① 가상환경 만들기 — 프로젝트에 한 번만.

# Windows
python -m venv .venv

# macOS / Linux
python3 -m venv .venv

② 활성화 — 터미널을 새로 열 때마다 필요. 입력줄 앞에 (.venv)가 붙으면 성공. 터미널 종류에 따라 명령이 다름.

# Windows · PowerShell (VS Code 기본. 입력줄 앞에 PS 표시)
.venv\Scripts\Activate.ps1

# Windows · 명령 프롬프트(cmd)
.venv\Scripts\activate.bat

# macOS / Linux
source .venv/bin/activate

③ 패키지 설치 — 반드시 (.venv)가 켜진 상태에서.

pip install requests python-dotenv
pip freeze > requirements.txt

④ 실행 — 활성화 상태에서 그냥 python.

python .claude/skills/background-collect/collect_news.py
  • .venv/와 .env는 .gitignore에 넣을 것. 공유는 requirements.txt로만.
  • VS Code에서 Ctrl+Shift+P → Python: Select Interpreter → .venv 선택하면 터미널이 자동 활성화됨.
  • 막히면 Claude Code에 "내 OS는 Windows야. .venv를 만들고 활성화하는 명령을 알려줘"라고 요청.

가장 흔한 사고 두 가지 — ① ModuleNotFoundError는 대개 활성화를 안 한 상태로 실행한 경우임. (.venv) 표시부터 확인. ② PowerShell에서 활성화가 차단되면 .venv\Scripts\activate.bat을 쓰는 것이 가장 빠른 해결임(실행정책 제한을 받지 않음). PowerShell을 유지하려면 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned를 한 번 실행. 자세한 내용은 입문 가이드 사전 준비 2.

3-3. 네이버 검색 API 키

developers.naver.com에서 애플리케이션을 등록하고 검색 API를 추가하면 Client ID와 Secret 발급. 무료·즉시 발급. 프로젝트 루트의 .env에 저장.

NAVER_CLIENT_ID=발급받은_ID
NAVER_CLIENT_SECRET=발급받은_SECRET

웹 배경 보완은 Claude Code 내장 WebSearch로 처리. 추가 설정 불필요.

네이버 뉴스 API의 한계를 미리 알아 둘 것. 한 검색어당 최대 1000건, 최신순 정렬 시 최근 몇 주치에서 끊김. 실제로 검색어 3개로 848건을 모았을 때 기간이 약 6주에 그침.

따라서 몇 년에 걸친 장기 배경은 이 API만으로 채울 수 없음. 두 가지로 보완.

① 정렬을 sim(정확도순)으로 바꿔 다른 구간을 한 번 더 수집.
② 연혁·초기 경과는 web-researcher 서브에이전트의 WebSearch로 1차 출처(정부 보도자료·기관 보고서)에서 확보.

소속 언론사가 빅카인즈 API를 쓸 수 있다면 이 단계를 빅카인즈로 교체하는 편이 나음. 104개 매체의 장기 아카이브와 인용문·개체명을 함께 제공하기 때문.

# 취재보도 에이전트 프로젝트 규칙

## 역할과 원칙 (세 회차 공통)
- 너는 취재 보조다. 판단·섭외·게재 책임은 사람 기자에게 있다.
- 사실·수치·인용은 지어내지 않는다. 근거가 없으면 [확인 필요].
- 모든 항목에 출처(기사·문서·URL·쪽수)를 단다.
- 기사 전문을 복제·저장하지 않는다. 메타데이터·짧은 인용·링크만 쓴다(저작권).
- 인물 정보는 공개된 역할·직위 기준으로만 다루고, 사생활·미확인 혐의를 단정하지 않는다.
- 모든 설명은 한국어로.

## 폴더 규약 (세 회차 공통)
- 1_plan/   기획 산출물 (이번 회차)
- 2_sources/ 2_facts/  취재 산출물 (2막)
- 3_story/  기사 산출물 (3막)
- 앞 회차의 파일은 읽기만 하고 덮어쓰지 않는다.

## 파이썬 실행 환경 (세 회차 공통)
- 패키지는 프로젝트 폴더의 .venv 가상환경에 pip로만 설치한다. 전역 설치 금지.
- 스크립트 실행 전 .venv 활성화 여부를 확인하고, 안 돼 있으면 활성화 방법을 사람에게 알려준다.
- 패키지를 새로 설치하면 requirements.txt 를 갱신한다.
- .venv/ 와 .env 는 .gitignore 에 넣는다.

## 질문 번호 규약 (중요)
- 취재 계획의 핵심 질문에는 Q1, Q2, Q3... 번호를 붙인다.
- 이 번호는 2막에서 수집 자료를, 3막에서 기사 문장을 되짚는 고리다.
- 한 번 부여한 번호는 바꾸지 않는다. 질문이 늘면 뒤에 이어 붙인다.

## 이번 회차(1막) 작업 순서 ("<주제> 취재 기획해줘"라고 하면 이 순서로)
1. news-archivist 서브에이전트로 과거 기사를 수집한다. → 1_plan/background_raw.md
2. web-researcher 서브에이전트로 웹 배경을 보완한다. → 1_plan/background_web.md

4. reporting-plan 스킬로 취재 계획을 설계한다. → 1_plan/reporting_plan.md (+ .html 보기용)
각 단계마다 무엇을 했는지 한 줄로 보고한다. 한 단계만 실행하라고 하면 그 단계만 한다.

## 윤리
- 언론사별 프레임 비교는 편향 해석에 주의한다.
- 인터뷰 대상·현장은 '제안'일 뿐, 실제 섭외·질문·촬영은 기자가 판단한다.
- 명예훼손·프라이버시 위험이 있으면 멈추고 사람에게 알린다.

# 과거 기사 수집 절차
1. 주제를 쟁점별 검색어 3~5개로 나눈다. 한 덩어리 검색어는 결과가 좁아진다.
2. collect_news.py 상단의 QUERIES 를 그 검색어로 고친다.
3. .venv 활성화 후 실행한다:  python .claude/skills/background-collect/collect_news.py
4. 출력된 '실제 기간'을 확인한다. 사안 대비 너무 짧으면 스크립트의 sort 를
   "date" → "sim" 으로 바꿔 한 번 더 돌리고, 결과를 합친다.
5. 기사 전문은 저장하지 않고 링크만 남긴다. API 호출 한도를 지킨다.

.claude/skills/background-collect/collect_news.py

"""네이버 뉴스 검색 API로 주제 관련 과거 기사 메타를 모은다.

기사 전문은 저장하지 않는다(저작권). 제목·언론사·날짜·링크만 남긴다.
"""
import html, json, os, pathlib, re, time, urllib.parse, urllib.request
from collections import Counter
from email.utils import parsedate_to_datetime
from dotenv import load_dotenv

load_dotenv()

# ── 여기만 고쳐 쓰세요 ────────────────────────────────
QUERIES = ["해상풍력 인허가", "해상풍력 국산화", "해상풍력특별법"]
MAX_PER_QUERY = 300          # 네이버 API 상한: 질의당 1000건
SORT = "date"                # 최신순. 기간이 짧으면 "sim"(정확도순)으로 한 번 더
OUT = pathlib.Path("1_plan") / "background_raw.md"
# ────────────────────────────────────────────────────

CID = os.environ["NAVER_CLIENT_ID"]
CSEC = os.environ["NAVER_CLIENT_SECRET"]


def strip_tags(s):
    """검색어 강조용 <b> 태그와 HTML 엔티티를 걷어낸다."""
    return html.unescape(re.sub(r"<[^>]+>", "", s or "")).strip()


def to_date(pub_date):
    """네이버가 주는 RFC822 날짜를 YYYY-MM-DD로. 타임라인 정렬에 필요하다."""
    try:
        return parsedate_to_datetime(pub_date).strftime("%Y-%m-%d")
    except (TypeError, ValueError):
        return "0000-00-00"


def search(query, want):
    items, start = [], 1
    while len(items) < want and start <= 1000:
        qs = urllib.parse.urlencode(
            {"query": query, "display": 100, "start": start, "sort": SORT}
        )
        req = urllib.request.Request(
            f"https://openapi.naver.com/v1/search/news.json?{qs}",
            headers={"X-Naver-Client-Id": CID, "X-Naver-Client-Secret": CSEC},
        )
        with urllib.request.urlopen(req, timeout=20) as r:
            batch = json.loads(r.read().decode("utf-8")).get("items", [])
        if not batch:
            break
        items.extend(batch)
        start += 100
        time.sleep(0.1)          # 호출 한도를 지킨다
    return items[:want]


seen, rows = set(), []
for q in QUERIES:
    got = search(q, MAX_PER_QUERY)
    print(f"  {q}: {len(got)}건")
    for it in got:
        link = it.get("originallink") or it.get("link")
        if not link or link in seen:
            continue
        seen.add(link)
        rows.append({
            "date": to_date(it.get("pubDate", "")),
            "title": strip_tags(it.get("title")),
            "desc": strip_tags(it.get("description"))[:120],
            "link": link,
            "domain": urllib.parse.urlparse(link).netloc.replace("www.", ""),
        })

rows.sort(key=lambda r: r["date"], reverse=True)

OUT.parent.mkdir(parents=True, exist_ok=True)
lines = [
    "# 배경 자료 — 과거 기사 메타", "",
    f"검색어: {' / '.join(QUERIES)}",
    f"수집: {len(rows)}건 (중복 링크 제거 후)",
    f"기간: {rows[-1]['date']} ~ {rows[0]['date']}" if rows else "", "",
    "> 기사 전문은 저장하지 않는다. 확인은 링크로 원문에서 한다.", "",
]
for i, r in enumerate(rows, 1):
    lines += [
        f"## N{i:03d}  {r['title']}",
        f"- 매체: {r['domain']} | 일자: {r['date']}",
        f"- 요약: {r['desc']}",
        f"- 링크: {r['link']}", "",
    ]
OUT.write_text("\n".join(lines), encoding="utf-8")

print(f"\n저장: {OUT}  ({len(rows)}건)")
if rows:
    print(f"실제 기간: {rows[-1]['date']} ~ {rows[0]['date']}")
print("매체 분포 상위 10:")
for dom, n in Counter(r["domain"] for r in rows).most_common(10):
    print(f"  {dom:<28} {n:>4}건")

실제로 돌려 확인한 결과 — 검색어 3개 · 질의당 300건으로 중복 제거 후 848건 수집. 뉴시스·비즈니스포스트·아주경제·매일경제·뉴스1·이데일리·전기신문 등으로 매체가 고르게 분포해 프레임 비교가 가능했음.

# 배경 브리프 작성 절차

5. 핵심 인용·팩트: 짧은 인용과 수치(출처 명기). 기사 전문은 복제하지 않고 링크한다.
6. 미확인·공백: 아직 확인 안 된 것, 상충하는 정보.
   ★ 이 6번이 다음 단계(취재 계획)의 질문 후보가 된다. 가장 공들여 쓴다.

# 취재 계획 설계 절차
입력은 1_plan/background_brief.md 다. 여기 있는 사실만 근거로 아래를 구성한다.
1. 취재 목표·가설: 확인할 스토리 한 줄과 그 근거.
2. ★ 핵심 질문 (이 회차의 핵심 산출물): 검증할 사실·쟁점을 질문 형태로 5~8개.
   - Q1, Q2, Q3... 번호를 붙인다. 이 번호는 2·3막에서 계속 쓰이므로 절대 바꾸지 않는다.
   - 각 질문은 공개기록으로 답이 나오는 형태여야 한다.
     좋음: "인허가에 평균 몇 개월 걸렸나?"  나쁨: "해상풍력은 바람직한가?"
   - 각 질문마다 [확인 방법]을 적는다. 어느 소스에서 무엇을 받아야 답이 나오는지.
     예) Q2 → DART 정기공시에서 해당 법인의 수주 공시를 특별법 시행일 전후로 비교
   - 각 질문마다 [근거]로 배경 브리프의 어느 항목에서 나온 의문인지 표시한다.
3. 필요한 자료·데이터: Q번호별로 묶어서 적는다.
   무엇을 어디서(공시=DART, 의안·회의록=열린국회정보, 뉴스=네이버, 그 외 기관 사이트).
   2막에서 그대로 수집 목록으로 쓸 수 있게 기관명·검색어·기간까지 구체적으로.
4. 인터뷰 대상 후보: 역할별로 나눈다(당사자, 담당 기관, 전문가, 이해관계자, 반대측).
   각 후보에 왜 필요한지와 물어볼 질문 2~3개를 적고, 어느 Q에 답하는지 표시한다.
   신원은 공개된 역할·직위 기준으로만 제안하고, 미확인 정보는 [확인 필요].
5. 현장 취재: 확인·관찰·촬영할 장소와 시점, 무엇을 볼지. 안전·촬영 동의·사유지 등 유의사항.
6. 예상 반론·리스크: 반대 측 주장, 오보 위험, 명예훼손·프라이버시 체크.
7. 일정·우선순위: 먼저 확인할 것부터.
모든 항목에 근거(기사·문서·URL)를 단다. 근거 없는 단정은 쓰지 않는다.
결과를 1_plan/reporting_plan.md 로 저장한다. 이 파일이 2막의 입력이다.
보기 좋은 1_plan/reporting_plan.html 도 함께 만든다(CSS 인라인, 상단에 주제·작성일,
하단에 "AI 초안이며 사람이 검토·확인해야 함" 고지).

5-1. 회차를 마치기 전에 — 인수인계 점검

2막은 이 회차의 산출물을 그대로 입력으로 씀. 다음 회차에서 막히지 않으려면 끝내기 전에 세 가지 확인 필요.

  • 질문에 번호가 붙어 있는가. Q1~Q8 정도. 번호 없는 질문은 2막에서 자료와 묶이지 않음.
  • 각 질문이 공개기록으로 답이 나오는가. "어떻게 생각하나" 류는 제거.
  • 기업·기관 이름이 정식 명칭인가. 2막에서 DART 공시를 법인명으로 조회하므로 "SK오션플랜트"처럼 정확해야 함. 약칭·별칭만 있으면 지금 바로잡을 것.

Claude Code에 아래처럼 지시하면 한 번에 점검됨.

1_plan/reporting_plan.md 를 읽고 인수인계 점검을 해줘.
질문에 Q번호가 다 붙었는지, 각 질문이 공개기록으로 답이 나오는 형태인지,
등장 기업·기관이 정식 명칭인지 확인하고 고칠 곳을 알려줘.

6. 윤리와 저작권 (반드시)

  • 기사 전문을 복제·저장하지 않음. 배경 브리프는 메타데이터·짧은 인용·요약·링크로 구성하고 원문은 링크로 연결.
  • 언론사별 프레임 비교는 참고일 뿐. 특정 매체를 단정적으로 재단하지 않음.
  • 인터뷰 대상·질문·현장 취재는 '제안'. 실제 섭외·질문·촬영은 기자가 판단하고 촬영 동의·사유지·안전을 준수.
  • 인물은 공개된 역할·전문성 기준으로만 다루고, 사생활·미확인 혐의를 단정하지 않음.
  • 취재 계획은 초안. 데스크·기자가 검토하며 최종 책임은 사람에게 있음.

7. 2시간 진행 순서

  • 0부(10분): 왜 배경부터인가 — "처음 맡은 주제를 30분에 파악"하고 질문 목록으로 잇기. 세 회차 전체 지도 보여주기.
  • 1부(20분): 세팅 — newsroom_agent/ 생성, .venv 만들고 활성화, pip install, .env(네이버 키), CLAUDE.md, 서브에이전트·스킬 파일.
  • 2부(30분): 과거 기사 수집·웹 배경 보완. 수집 기간과 매체 분포 확인.
  • 3부(25분): 배경 요약·논리 구성(타임라인·쟁점·프레임·공백).
  • 4부(25분): 취재 계획 설계 — 질문 Q1~Q8에 번호 붙이기, 질문별 확인 방법 적기.
  • 5부(10분): 인수인계 점검과 윤리·저작권 확인. 2막에서 무엇을 하는지 예고.

강사 메모: 4부가 이 회차의 승부처입니다. 배경 요약은 AI가 잘하지만, "자료로 답이 나오는 질문"으로 벼리는 일은 기자의 감각이 필요합니다. 수강생이 쓴 질문을 두세 개 띄워 놓고 "이건 어느 문서를 받아야 답이 나오나?"를 함께 되물으면, 2막의 수집 목록이 자연스럽게 만들어집니다.
