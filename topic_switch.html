주제 바꾸기 — 새 주제를 세 막 전체에 적용하기

해상풍력에서 배달앱 수수료로. 무엇을 고치고 무엇을 그대로 두나

대상: 해상풍력 주제로 1막~3막을 한 번 돌려 본 기자
목적: 같은 파이프라인에 새 주제를 갈아 끼우는 실습. 본인 출입처 주제로 옮길 때의 표준 절차
사례 주제: 배달앱 수수료는 누가 정하고 누가 부담하나
핵심 메시지: 파이프라인은 그대로. 바꾸는 것은 검색어·법인명·수집 대상 세 종류뿐

1. 이 문서가 답하는 질문

세 막을 한 번 돌려 본 뒤 가장 먼저 나오는 질문은 하나임. "내 출입처 주제로 바꾸려면 뭘 고쳐야 하나?"

답은 생각보다 짧음. 설계는 주제와 무관하고, 주제에 매인 것은 몇 군데 값뿐임.

1-1. 바꾸는 것은 세 종류뿐

종류무엇어디에
① 검색어 뉴스 검색어 3~5개, 의안 검색어 2~4개 collect_news.py의 QUERIES
fetch_assembly.py의 KEYWORDS
② 법인명 DART에서 조회할 정식 법인명과 기간 fetch_dart.py의 COMPANIES·BGN·END
③ 수집 대상 브라우저로 받을 부처·기관 사이트 Playwright MCP 프롬프트

바꾸지 않는 것 — CLAUDE.md의 역할·원칙·폴더 규약, 서브에이전트 5개의 지침, 스킬 8개의 절차, Q번호·F번호 규약, 팩트체크 방식, 폴더 구조. 이 설계가 주제와 무관하기 때문에 파이프라인이라고 부를 수 있음.

2. 주제를 고르는 세 조건

2-1. 조건 세 가지

아무 주제나 되는 것은 아님. 이 파이프라인이 굴러가려면 세 조건이 필요함.

조건이유확인 방법
① 세 소스에 공통 개체가 등장 2막 교차검증의 전제. 공시에만 나오는 이름은 대조할 상대가 없음 기업명 하나를 골라 DART·국회·뉴스에서 각각 검색
② 공개기록으로 답이 나오는 질문이 5개 이상 1막 산출물이 질문 목록이므로. "바람직한가" 류만 나오면 2막이 성립 안 됨 질문 초안을 써 보고 각각 "어느 문서를 받으면 답이 나오나" 자문
③ 쟁점이 둘 이상으로 갈림 3막 앵글 판단과 [상충] 발견의 재료 이해관계자를 나열해 보고 주장이 부딪히는 지점 확인

2-2. 15분 사전 점검

본격 시작 전 15분만 투자해 세 소스를 확인. 여기서 걸러내면 3시간을 아낌.

① 뉴스 — 검색어가 성립하는가

"배달앱 수수료", "배달의민족 수수료", "온라인플랫폼법" 세 검색어로
네이버 뉴스 API를 각각 30건씩만 받아서, 실제로 같은 사안을 다루는지 제목만 보여줘.
검색어가 너무 넓거나 좁으면 대안도 제안해줘.

② 국회 — 의안이 있는가

fetch_assembly.py 의 KEYWORDS 를 ["온라인플랫폼", "배달"]로 바꿔 실행하고,
몇 건이 잡히는지와 대표발의 상위 의원만 보고해줘. 파일 저장은 하지 마.

③ DART — 법인이 조회되는가

fetch_dart.py 의 기업 목록 캐시를 이용해서
"우아한형제들", "쿠팡", "위대한상상"이 DART에 정식 법인명으로 등록돼 있는지 확인해줘.
상장 여부와 corp_code 도 함께 알려줘. 공시 조회는 아직 하지 마.

판정 기준 — 세 소스 모두에서 이름이 겹치는 개체가 최소 2개 나오면 진행. 하나도 안 겹치면 주제 범위를 좁히거나 넓혀 다시 시도.

3. 새 주제 — 배달앱 수수료

3-1. 왜 이 주제인가

  • 생활 밀착도 최상 — 자영업자는 비용, 소비자는 가격으로 직접 체감. 취재 동기와 독자 관심이 뚜렷함.
  • 이해관계가 정면으로 충돌 — 플랫폼 · 입점 자영업자 · 소비자 · 라이더. 3막 앵글 토론이 풍부해짐.
  • 세 소스가 모두 살아 있음 — 국회 의안, 기업 공시, 뉴스 모두 확보 가능(2-2절에서 직접 확인).
  • 해상풍력과 영역이 완전히 다름 — 에너지 → 플랫폼. 파이프라인이 주제에 매여 있지 않다는 것을 보여주는 데 적합.

3-2. 쟁점 지도

쟁점다투는 지점답이 있을 만한 소스
중개수수료율 요금제별 실제 부담률. 정률제 전환 이후 얼마나 올랐나 플랫폼 공지·약관, 공정위·중기부 보도자료, 업계 조사
배달비 전가 수수료 외 배달비·결제수수료·광고비를 합한 총부담 자영업자 단체 조사, 국회 국정감사 자료
이중가격제 매장가와 배달가 차이. 소비자 전가 여부 뉴스, 소비자단체 조사
상생협의체 합의 이행 합의된 인하안이 실제로 적용됐나 정부 보도자료, 플랫폼 공시·공지, 후속 보도
플랫폼 수익구조 수수료 수익이 매출·영업이익에서 차지하는 비중 DART 감사보고서·사업보고서

주의 — 이 표는 취재 출발점이지 사실이 아님. 수치·시점·합의 내용은 모두 2막에서 공개기록으로 직접 확인해야 함. 이 문서에 적힌 회사명·법 이름도 실습 시점에 DART·국회 API로 다시 검증할 것.

4. 1막(기획)에서 바꿀 것

4-1. 검색어 — collect_news.py

고치는 곳은 상단 설정 블록 한 줄.

# ── 여기만 고쳐 쓰세요 ────────────────────────────────
# 이전(해상풍력)
# QUERIES = ["해상풍력 인허가", "해상풍력 국산화", "해상풍력특별법"]

# 새 주제(배달앱 수수료)
QUERIES = ["배달앱 수수료", "배달앱 상생협의체", "온라인플랫폼법", "배달앱 이중가격"]
MAX_PER_QUERY = 300
SORT = "date"
OUT = pathlib.Path("1_plan") / "background_raw.md"
# ────────────────────────────────────────────────────

검색어 설계 원칙 — 쟁점별로 나눌 것. 한 덩어리로 넣으면 결과가 좁아짐.

잘못된 검색어왜고친 검색어
배달너무 넓음. 배달 사고·배달 로봇까지 섞임배달앱 수수료
배달앱 수수료 인하 상생협의체 합의너무 좁음. 한 덩어리 검색어는 결과가 급감배달앱 수수료 + 배달앱 상생협의체로 분리
배민약칭. 기사 표기가 제각각이라 누락 발생배달의민족 (필요하면 약칭도 별도 검색어로 추가)

수집 후 반드시 기간 확인. 네이버 뉴스 API는 최신순 정렬 시 최근 몇 주에서 끊김. 사안 대비 기간이 짧으면 SORT를 "sim"으로 바꿔 한 번 더 수집해 합칠 것. (1막 3-3절 참고)

4-2. 서브에이전트 예시 문구 (선택)

news-archivist.md의 지침에 해상풍력 예시가 들어 있음. 기능에는 영향이 없지만 헷갈리면 바꿔 둘 것.

# 이전
- 검색어는 한 덩어리로 넣지 말고 쟁점별로 나눈다. 예: "해상풍력 인허가" / "해상풍력 국산화" / "해상풍력특별법".

# 이후
- 검색어는 한 덩어리로 넣지 말고 쟁점별로 나눈다. 예: "배달앱 수수료" / "배달앱 상생협의체" / "온라인플랫폼법".

나머지 지침은 손대지 말 것 — "기사 전문을 복제하지 않는다", "수집 후 기간을 확인한다", "매체가 몰려 있으면 보고한다" 같은 규칙은 주제와 무관한 취재 원칙임.

4-3. 실행 프롬프트

<주제> 자리만 교체. 나머지 문장은 동일.

"배달앱 중개수수료와 상생협의체 합의 이행" 취재 기획해줘. CLAUDE.md 순서대로
과거 기사 수집 → 웹 배경 보완 → 배경 요약·구성 → 취재 계획 설계까지 진행하고,
단계마다 한 줄로 보고해.

4-4. 나올 질문 목록의 모습

1막의 산출물은 공개기록으로 답이 나오는 질문. 주제만 바뀌고 형식은 동일함.

Q1  주요 배달앱의 중개수수료율은 요금제별로 얼마이고, 최근 2년간 어떻게 바뀌었나?
Q2  상생협의체에서 합의된 인하안은 무엇이고, 언제부터 실제로 적용됐나?
Q3  수수료 외에 자영업자가 부담하는 항목(배달비·결제수수료·광고비)은 각각 얼마인가?
Q4  플랫폼 매출에서 중개수수료가 차지하는 비중은 얼마이고 어떻게 변했나?
Q5  국회에 발의된 플랫폼 규제 법안은 몇 건이고, 누가 대표발의했나?
Q6  공정위·중기부가 제재하거나 시정 권고한 사례는 무엇인가?
Q7  이중가격제를 도입한 업소 비율에 관한 공식 조사가 있는가?
Q8  라이더 배달료 단가는 같은 기간 어떻게 변했나?
이 질문이 좋은 이유예시
답할 문서가 특정됨Q4 → DART 감사보고서의 매출 구성
수치로 검증 가능Q1 → 요금제 공지의 수수료율
시점 대조가 가능Q2 → 합의 발표일 전후 공지·보도 비교
[상충]이 나올 여지가 있음Q3 → 플랫폼 발표 부담률 vs 자영업자 단체 조사

이런 질문은 걸러낼 것 — "배달앱 수수료는 적정한가?", "플랫폼 규제는 필요한가?", "자영업자들은 어떻게 생각하나?" → 공개기록으로 답이 나오지 않음. 1막 인수인계 점검에서 반드시 제거.

5. 2막(취재)에서 바꿀 것

5-1. 법인명 찾기 — 가장 중요한 단계

주제 전환에서 사고가 가장 많이 나는 지점. DART는 회사를 정식 법인명으로만 다룸. 브랜드명·약칭으로는 조회되지 않음.

흔히 쓰는 이름DART에서 찾아야 할 것
배달의민족, 배민운영 법인의 정식 명칭 (일반적으로 우아한형제들)
쿠팡이츠국내 제출 법인 (일반적으로 쿠팡 계열 법인)
요기요운영 법인의 정식 명칭 (일반적으로 위대한상상)

위 이름을 그대로 믿지 말 것. 법인은 사명 변경·분할·합병이 잦음. 반드시 실습 시점에 DART 기업 목록에서 직접 확인할 것. 확인 명령은 아래.

fetch_dart.py 가 캐시해 둔 .cache/CORPCODE.xml 을 읽어서
"우아한형제들", "쿠팡", "위대한상상" 이 들어간 법인명을 모두 찾아줘.
각각 corp_code 와 stock_code(상장 여부)를 표로 보여주고,
정확히 일치하는 이름이 없으면 비슷한 후보도 알려줘.

비상장 법인이 섞이는 문제

해상풍력 주제는 대상이 모두 상장사였음. 배달앱은 다름. 비상장 법인이 섞임.

구분DART에 올라오는 것실습에 미치는 영향
상장사 사업보고서·분기보고서·수시공시(계약·지분 등) 공시 건수가 많음. 시점 대조가 쉬움
비상장 외부감사 대상 주로 감사보고서. 수시공시는 거의 없음 건수가 적음. 대신 재무제표에서 매출 구성·수수료 수익을 확인 가능

이것 자체가 좋은 교육 소재. "공시가 3건밖에 안 잡히는데요?"라는 질문이 나오면, 비상장사는 수시공시 의무가 다르다는 점을 설명할 기회임. 이때 취재 전략은 건수가 아니라 감사보고서 본문으로 옮겨감.

5-2. fetch_dart.py

# ── 여기만 고쳐 쓰세요 ────────────────────────────────
# 이전(해상풍력)
# COMPANIES = ["씨에스윈드", "SK오션플랜트", "유니슨", "두산에너빌리티"]
# BGN, END = "20260101", "20260630"

# 새 주제(배달앱) — 5-1절에서 확인한 정식 법인명을 넣을 것
COMPANIES = ["우아한형제들", "쿠팡", "위대한상상"]
BGN, END = "20240101", "20260630"   # 상생협의체 논의 전후를 덮도록 넓게
# ────────────────────────────────────────────────────

기간 설정 요령

  • 비상장사는 연 1회 감사보고서 중심이므로 기간을 넓게 잡아야 건수가 나옴.
  • 다만 한 번에 100건까지만 오므로, 상장사가 섞여 있으면 total_count가 100을 넘는지 확인하고 기간을 쪼갤 것.
  • 쟁점의 분기점(합의 발표·법 시행 등)을 기간 한가운데에 두면 전후 비교가 쉬움.

5-3. fetch_assembly.py

# ── 여기만 고쳐 쓰세요 ────────────────────────────────
# 이전(해상풍력)
# KEYWORDS = ["해상풍력", "재생에너지", "풍력"]

# 새 주제(배달앱)
KEYWORDS = ["온라인플랫폼", "플랫폼 중개", "가맹사업"]
AGE = "22"
# ────────────────────────────────────────────────────

이 API는 의안 제목으로 검색함. "배달앱"은 법 제목에 거의 안 들어감. 법률 용어로 바꿔 넣어야 함 — 배달앱(×) → 온라인플랫폼(○). 주제를 바꿀 때마다 "이 사안을 다루는 법률의 이름은 무엇인가"를 먼저 확인할 것.

확인이 어려우면 AI에게 먼저 물어볼 것.

배달앱 수수료를 규율하는 국내 법률·법안의 정식 명칭 후보를 알려줘.
그 이름들이 국회 의안 제목에 실제로 쓰이는지 fetch_assembly.py 로 각각 10건씩만 확인해줘.

  적용 시작일, 조사 주체와 표본 수.

나머지 규칙은 절대 건드리지 말 것 — "위치를 반드시 적는다", "해석·추측하지 않는다", "검증 담당이 오염되면 안 된다". 이 규칙들이 2막 설계의 전부임.

6. 3막(보도)에서 바꿀 것

거의 없음. 3막의 입력은 사실 대장 하나뿐이고, 앵글 판단·문체·팩트체크는 모두 주제와 무관한 절차임.

CLAUDE.md 뉴스가치 절그대로다만 아래 강조점 차이는 알아 둘 것

강조되는 뉴스가치가 달라짐

주제강하게 작동하는 뉴스가치앵글이 잡히는 방향

강의 활용 포인트 — 같은 파이프라인, 같은 스킬인데 앵글 후보의 성격이 달라지는 것을 두 주제로 비교해 보여줄 수 있음. 뉴스가치가 취향이 아니라 사안의 성질에서 나온다는 점을 체감시키기 좋음.

7. 바꾸지 않는 것 (한 번 더)

주제를 바꿀 때 손대면 안 되는 것을 다시 정리함. 여기를 건드리면 파이프라인이 무너짐.

영역그대로 두는 이유
Q번호 · F번호 규약 세 막을 잇는 유일한 고리. 번호 체계를 바꾸면 되짚기가 끊김
추출자와 검증자 분리 팩트체크 신뢰의 핵심. 주제와 무관한 구조적 장치
[확인]·[미확인]·[상충] 3단 표시 3막에서 무엇을 쓸 수 있고 없는지를 결정하는 기준
"대장에 없는 문장은 쓰지 않는다" 환각 차단 장치. 이 규칙 하나가 전체 신뢰를 지탱
출처를 원본 쪽수로 적는 규칙 변환본은 수치가 어긋날 수 있음. 사람이 되짚을 때 필요
수집 전 목록 승인 API 한도·되돌리기 어려움 때문. 주제와 무관
윤리·저작권 규칙 기사 전문 복제 금지, 로그인 우회 금지, 미확인 혐의 단정 금지

8. 흔한 실패와 대처

증상원인대처
DART에서 [찾을 수 없음] 브랜드명·약칭을 넣음 5-1절 명령으로 정식 법인명 확인 후 교체
공시가 몇 건뿐 비상장 법인이라 수시공시가 적음 정상. 기간을 넓히고 감사보고서 본문으로 전략 전환
의안이 0건 일상어를 검색어로 넣음(배달앱) 법률 용어로 교체(온라인플랫폼). 5-3절 확인 프롬프트 사용
뉴스가 수천 건이라 정리 불가 검색어가 너무 넓음(배달) 쟁점별로 좁힘. MAX_PER_QUERY도 낮출 것
뉴스 기간이 3주뿐 네이버 API의 최신순 정렬 한계 SORT를 "sim"으로 바꿔 한 번 더 수집해 합침
세 소스에 겹치는 개체가 없음 주제 범위가 어긋남 2-2절 사전 점검으로 복귀. 주제를 좁히거나 인접 사안으로 이동
질문이 전부 "어떻게 생각하나" 류 쟁점을 의견 문제로 잡음 각 질문에 "어느 문서를 받으면 답이 나오나"를 붙여 다시 씀
사실 대장이 전부 [확인] 교차검증이 형식적이었음 verifier에게 "처음 나온 곳과 다른 출처로 확인"을 다시 명시

9. 내 출입처 주제로 바꾸기 — 체크리스트

배달앱 사례를 따라 해 본 뒤, 본인 주제로 옮길 때 쓰는 목록.

  • [ ] 주제를 한 문장으로 적었는가. (예: "○○의 △△는 누가 정하고 누가 부담하나")
  • [ ] 2-1절 세 조건을 모두 만족하는가.
  • [ ] 2-2절 15분 사전 점검을 실제로 돌려 봤는가.
  • [ ] 세 소스에 겹치는 개체가 2개 이상 나왔는가.
  • [ ] 새 폴더를 만들고 .claude/·CLAUDE.md를 복사했는가.
  • [ ] .venv를 새로 만들고 requirements.txt로 패키지를 복원했는가.
  • [ ] QUERIES를 쟁점별 3~5개로 나눠 넣었는가.
  • [ ] DART 정식 법인명을 실제 조회로 확인했는가.
  • [ ] 의안 검색어를 법률 용어로 바꿨는가.
  • [ ] 브라우저 수집 대상 부처·기관을 교체했는가.
  • [ ] 쟁점의 분기점이 DART 조회 기간 안에 들어가는가.
  • [ ] 7장의 바꾸지 않는 것을 건드리지 않았는가.

10. 90분 진행 순서 (전환 실습)

세 막을 이미 마친 수강생 대상. 전 과정을 다시 돌리지 않고 바꾸는 지점만 훑는 구성.

  • 0부(10분): 왜 주제를 바꿔 보나 — 파이프라인과 주제의 분리. 1-2절 변경 지도 화면에 띄우기.
  • 1부(15분): 2-2절 15분 사전 점검을 각자 실행. 세 소스에서 겹치는 개체 찾기.
  • 2부(15분): 새 폴더 만들고 설정 복사, .venv 재생성, QUERIES 교체 후 뉴스 수집.
  • 3부(20분): 법인명 찾기(5-1절)와 fetch_dart.py·fetch_assembly.py 교체. 이 회차의 승부처.
  • 4부(15분): 1막 질문 목록 생성. 해상풍력 때와 형식은 같고 내용만 다른 것을 확인.
  • 5부(10분): 두 주제의 앵글 후보 비교(6장). 뉴스가치 강조점이 왜 달라지는지 토론.
  • 6부(5분): 9장 체크리스트로 본인 출입처 주제 검토.

강사 메모 — 3부가 승부처임. "배민"으로 조회했다가 [찾을 수 없음]이 뜨고, 정식 법인명으로 바꿔 조회에 성공하는 장면을 일부러 겪게 할 것. 공공데이터가 브랜드가 아니라 법인 단위로 관리된다는 사실이 이 한 장면으로 각인됨.

또 하나 유용한 장면은 비상장사의 공시 건수가 적게 나오는 것. "데이터가 없다"가 아니라 "제도가 달라서 다른 문서를 봐야 한다"로 해석을 바꿔 주면, 공개기록 취재의 감각이 한 단계 올라감.
