3막 문서 열기

세 막이 이어지는 방식

막과 막 사이를 잇는 것은 설명이 아니라 파일. 앞 막의 산출물이 뒷 막의 입력 경로가 됨.

중간에 합류해도 됨. 각 막의 시작 지점에 이전 단계 산출물 배포본을 함께 제공. 2막부터 참여하면 1_plan/을, 3막부터 참여하면 2_facts/를 풀어놓고 그 자리에서 시작.

실습 주제 — 두 가지 중 선택

세 막이 하나의 사슬로 이어지려면 주제가 하나여야 함. 아래 두 주제 중 하나를 골라 세 회차 내내 유지.

주제 선정 기준은 하나

같은 기업·의원 이름이 공시와 의안과 기사에 반복 등장해야 함. 2막의 교차검증 실습은 이 조건이 갖춰져야 실제로 굴러감. 쟁점이 뚜렷해야 1막의 취재 기획도 성립함.

아래 두 주제는 이 조건을 모두 만족함. 본인 출입처 주제로 바꿔도 되지만, 세 소스에서 공통 개체가 잡히는지 1막에서 먼저 확인할 것. 주제를 바꿀 때 무엇을 고쳐야 하는지는 주제 바꾸기 가이드에 단계별로 정리해 둠.

주제 A · 기본

재생에너지 전환의 돈과 규칙
— 해상풍력을 사례로

쟁점: 인허가 지연 · 국산화율 · 보조금 · 주민수용성.

강점: 상장 제조사가 여럿이라 공시가 두텁고, 특별법·지원법 의안이 많아 국회 데이터가 풍부함.

국회
22대 의안 — 재생에너지 56건 · 해상풍력 12건 · 태양광 10건. 발의 의원 명단까지 확보
DART
씨에스윈드 · SK오션플랜트 · 유니슨 · 두산에너빌리티 등 상장사 공시
뉴스
배경 파악과 언론사별 프레임 비교
주제 B · 생활 밀착

배달앱 수수료는 누가 정하고
누가 부담하나

쟁점: 중개수수료율 · 배달비 전가 · 이중가격제 · 상생협의체 합의 이행.

강점: 자영업자와 소비자 양쪽에 직접 영향. 취재 동기와 독자 관심이 뚜렷해 앵글 잡기가 쉬움.

국회
온라인플랫폼 중개거래 공정화법 등 플랫폼 규제 의안 다수
DART
우아한형제들(비상장·감사보고서 제출) · 쿠팡㈜ 등 국내 법인 공시
뉴스
수수료 인상·상생협의체 보도 대량. 시점 대조에 유리

어느 쪽을 고를까. 데이터가 가장 두텁고 예시 코드가 그대로 맞는 쪽은 주제 A(해상풍력). 수강생이 취재 동기를 바로 느끼고 앵글 토론이 활발한 쪽은 주제 B(배달앱 수수료). 강의 시간이 넉넉하면 A로 전 과정을 돌린 뒤 B로 주제 전환 실습을 하는 구성이 가장 효과적임.

강의 전 준비물

수강생에게는 사전 준비 안내문과 스타터 zip을 보내면 됩니다. 안내문 하나로 아래 내용이 단계별로 정리돼 있고, 20분이면 끝납니다. 1막만 진행한다면 네이버 키 하나만 있으면 되므로 사전 부담이 작습니다.

① 파이썬과 가상환경

  • 파이썬 3.11 이상 설치. Windows는 설치 중 "Add python.exe to PATH" 체크 필수.
  • 프로젝트 폴더에서 python -m venv .venv → 활성화 → pip install. 자세한 절차는 입문 가이드 사전 준비 2.

② AI 코딩 도구 (한 가지만 준비해도 됨)

  • Claude Code(Anthropic 계정) 또는 OpenAI Codex(ChatGPT 계정). 문서는 Claude Code 기준이며, 각 문서 마지막의 "Codex로 만들기" 절에 대체 방법이 있음.
  • 구글 Antigravity CLI(agy)는 무료 한도가 빡빡해 실습 기본 도구로는 비권장.

③ API 키 — 2차 실습은 공개 API를 직접 호출함. 아래 키를 미리 발급받아 .env에 저장할 것. 발급은 모두 무료이며 신청 즉시 또는 하루 안에 승인됨.

DART_API_KEY — 금융감독원 전자공시 · opendart.fss.or.kr
ASSEMBLY_API_KEY — 열린국회정보 · open.assembly.go.kr
NAVER_CLIENT_ID / NAVER_CLIENT_SECRET — 네이버 검색 API · developers.naver.com

공공데이터포털(data.go.kr)은 선택 심화. 이곳은 키를 발급받아도 API마다 따로 "활용신청"을 해야 하고, 신청하지 않은 API는 키가 있어도 SERVICE_KEY_IS_NOT_REGISTERED_ERROR로 막힘. 쓸 계획이면 강의 전에 해당 API를 신청해 둘 것.

Codex로 대체하기

모든 문서는 Claude Code 기준으로 작성했지만, OpenAI Codex로도 전 과정을 그대로 진행할 수 있음. 수강생 중 ChatGPT 구독자가 많다면 이 경로를 쓰면 됨. 개념이 1:1로 대응되고 파일 이름·형식과 실행 명령만 다름.

프로젝트 지침 CLAUDE.md → AGENTS.md. 파일명만 바꾸고 내용은 그대로 사용.
서브에이전트 .claude/agents/<이름>.md → .codex/agents/<이름>.toml. 마크다운 프론트매터를 TOML 키(name·description·developer_instructions)로 옮김.
스킬 SKILL.md 형식은 동일. 위치만 Codex 규칙에 맞추고 대화에서 $스킬이름으로 호출.
MCP 연결 .mcp.json → ~/.codex/config.toml의 [mcp_servers]. JSON을 TOML로 변환.
실행과 권한 폴더에서 codex 실행. 계획은 /plan, 실행은 /exec, 확인은 /diff. 권한은 샌드박스 workspace-write 권장.

각 문서 마지막의 "Codex로 만들기" 절에 해당 회차의 파일별 변환 방법과 주의점을 자세히 정리해 둠. Codex는 diff 미리보기가 약하므로 바뀐 파일을 반드시 직접 확인할 것.

기자를 위한 바이브 코딩 학습 허브 — 1차 도구 익히기, 2차 기획·취재·보도 실습. AI는 단서를 모아 주는 도구이며, 확인과 게재의 책임은 사람 기자에게 있습니다. 도구 버전·API 사양은 2026년 8월 기준이며 자주 바뀝니다.
